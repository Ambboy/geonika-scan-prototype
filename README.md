# Геоника · поверхности из реального 3D-скана

Исследовательский прототип: лёгкая цветная модель измеренного объекта в браузере. По умолчанию показаны **настоящие треугольные поверхности**, а не увеличенные точки. Прокрутка ведёт камеру по демонстрационному маршруту; свободный осмотр позволяет вращать и приближать модель. Это отдельный прототип, не замена существующего сайта компании.

## Что показано

- Реконструкция построена из полных LAS: **97 486 182** точки внутри и **49 524 269** снаружи. Все записи участвовали в ограниченной по памяти 65-мм voxel-агрегации.
- Экстерьер: **104 298 треугольников**, `3 511 104` байта. Интерьер: **148 624 треугольника**, `4 987 732` байта. Оба GLB вместе — **8 498 836 байт**.
- Метод: очистка разреженных/шумовых участков, нормали, BPA, регуляризация поддержанных измерениями плоскостей, локальное заполнение поддержанных пробелов, удаление отсоединённых фрагментов, QEM-упрощение и перенос измеренного RGB.
- Координаты источника сохранены, вертикальная ось — Z. Стандартные Y-up GLB возвращаются в source frame обратным поворотом, без отражения осей. Наличие известного геодезического CRS не заявляется.
- Точные размеры, количества, границы, SHA-256, метод и ограничения находятся в `public/data/surfaces.json`. В GLB — позиции, нормали и Linear-sRGB vertex color; внешних текстур, URI или декодеров нет.
- Режим **«Точки»** сохранён для сравнения: 600 000 наружных и 900 000 внутренних точек, всего 24 000 000 байт. Эти BIN не загружаются, пока режим не выбран. Повторное переключение использует проверенный кеш текущей страницы.
- Первая точечная версия сохранена в Git-истории. Исходные многогигабайтные LAS и архивы в репозиторий не входят и не изменяются.

## Качество и ограничения реконструкции

Это автоматически восстановленная черновая поверхность, **не BIM, не watertight-модель и не фотореалистичный интерьер**. Основные стены и полы читаются как поверхности, но мебель, остекление, мелкие детали и границы съёмки остаются фасетными или с прорехами. Неизмеренные части здания не придуманы.

Плоскости могут локально сдвигаться до 4 см; поддержанное заполнение способно перекрывать пробелы меньше 23 см. Удалены 1 244 261 шумовой/разреженный occupied voxel; ещё 659 571 объединены при resampling — это не то же самое, что удаление шума и не число исходных LAS-точек.

Расстояния **mesh → референс полной 65-мм агрегации LAS**, median / p95 / max:
- exterior: 0,03063 / 0,06370 / 0,13296 м;
- interior: 0,02954 / 0,04959 / 0,12303 м.

Референс состоит из центроидов voxel, сформированных по всем записям LAS, с дополнительным условием **не менее четырёх исходных записей в voxel**. Это не сырые LAS-точки и не все занятые voxel; названия метрик в манифесте сохраняются для совместимости.

Это метрика поддержки построенной поверхности, **не гарантия инженерной точности и не полнота скана**. Обратное расстояние очищенные точки → mesh имеет exterior p95 **2,90 м**: часть периферии, растительности и отсоединённых фрагментов намеренно удалена. Покрытие очищенных точек в пределах 25 см — 85,573% exterior и 99,0345% interior. Полные направления метрик опубликованы в манифесте, а не скрыты за одной удачной цифрой.

## Управление

- Прокрутка — вперёд и назад по пяти главам; кнопки глав — переход к виду.
- **Поверхности / Точки** — сравнение представлений без сброса камеры.
- **Свободный осмотр** — вращение и приближение вместо управления маршрутом; Escape возвращает к маршруту.
- **Срез** — настоящее отсечение геометрии по мировой оси Z, не только изменение подписи.
- Состояние загрузки, проверка целостности, ошибки и повторная загрузка видимы. «Готово» означает реальный draw выбранного типа и загрузку обеих необходимых моделей, а не только получение байтов.

Маршрут демонстрационный: это не проверенный проход через конкретные двери и не навигация с коллизиями. Автоматическая мобильная проверка не заменяет физический iPhone/Safari.

## Запуск, тесты и сборка

Нужен Node.js, совместимый с закреплённым Vite (см. `package.json`). Для просмотра и сборки Python не нужен.

```sh
npm ci
npm test
node e2e/surface-gate.mjs
npm run dev -- --host 127.0.0.1
```

`surface-gate.mjs` читает реальные GLB, проверяет размер/SHA, standalone-структуру, оси, цвета, нормали и фактические количества. Его `PASS_ASSETS_ONLY_NOT_GPU` не означает браузерную приёмку.

```sh
npm run build
npm run test:e2e
```

Результат production-сборки — `docs/`. Playwright запускает временный loopback-only preview под `/geonika-scan-prototype/`. Для собственного Chrome задайте `SCAN_BROWSER_EXECUTABLE`; для отдельного build/evidence — `SCAN_BUILD_DIR` / `SCAN_EVIDENCE_DIR`. Проверяются реальные треугольники и точки, оба направления scroll, orbit/return, Z-срез, мобильный viewport, отложенный interior, lazy-загрузка, кеш, повреждённые файлы, retry и WebGL fallback.

## Повторная реконструкция поверхностей

Проверенная среда — Linux CPU / Python 3.13, отдельный venv с `requirements-surfaces.txt`. На минимальном Linux Open3D требует также runtime `libEGL1`. Не устанавливайте эти пакеты в рабочую среду бота.

```sh
python3 -m venv /path/to/private/mesh-venv
/path/to/private/mesh-venv/bin/python -m pip install -r requirements-surfaces.txt
/path/to/private/mesh-venv/bin/python -B -m unittest discover -s tests -p test_reconstruct_surfaces.py -v

/path/to/private/mesh-venv/bin/python -u -B tools/reconstruct_surfaces.py \
  --source-dir /path/to/private/extracted \
  --evidence-dir /path/to/private/mesh-evidence \
  --stage reconstruct --model both
# Просмотрите реальные color/clay-превью кандидатов перед финализацией.
/path/to/private/mesh-venv/bin/python -u -B tools/reconstruct_surfaces.py \
  --source-dir /path/to/private/extracted \
  --evidence-dir /path/to/private/mesh-evidence \
  --output-dir public/data --stage finalize
node e2e/surface-gate.mjs
```

В source-dir ожидаются `exterior.las` и `interior.las` с закреплёнными исходными SHA/count/bytes. Свежий evidence-dir запускает полную агрегацию; повторное использование кеша требует совпадения SHA исходника и кеша. Сравниваются BPA и поддержанный planar+BPA hybrid. Превью, промежуточные кандидаты и отчёты сохраняйте вне публичного дерева. Наличие готовых asset-файлов само по себе не доказывает визуальное качество.

## Повторная подготовка точек для сравнения

Формат выборки описан в `PROJECT_BRIEF.md`. Нужны Python 3.10+, NumPy и системная libarchive.

```sh
python3 -B tools/prepare_scan.py \
  --archive /path/to/las.7z \
  --extract-dir /path/to/private/extracted \
  --output-dir public/data \
  --evidence-dir /path/to/private/point-evidence \
  --expect-archive-sha256 99cbfbba2cad6874c05189fa1d6803499a172d6cbc1409d106cad5c7514aa14a \
  --exterior-points 600000 --interior-points 900000 \
  --seed 20261107 --chunk-points 1000000
python3 -B -m unittest discover -s tests -p test_prepare_scan.py -v
```

В каждой равной индексной страте выбирается одна существующая точка, не первые N записей. Эти ранее проверенные BIN и их манифест при реконструкции поверхностей не меняются.
