# Реальные поверхности вместо точек — версия 2

## Задача и критерии

По реальным исходным LAS построить интерьер и экстерьер со сплошными поверхностями, удалить шум и сделать лёгкую модель для браузера. Не заменять исходник красивой картинкой, спрайтами, увеличенными точками, cuboid-заглушками или другой моделью. Не требуется инженерная/BIM-точность и ручное восстановление всех невидимых деталей. Реконструированные участки и их погрешность должны быть честно обозначены.

Первый вариант с облаками сохраняется в Git-истории, сами исходные LAS/архивы не меняются. Публикация новой версии допускается только после просмотра настоящих mesh-кадров и проверки улучшения относительно точек.

## Геометрия

- Основная база — полные LAS внутри и снаружи, а не только веб-выборка 1,5 млн точек.
- Обработка ограниченными чанками; полный исходник нельзя целиком размножать в RAM.
- Рекомендуемый порядок: voxel-агрегация → статистическая/соседская очистка → оценка нормалей → выделение и выравнивание реально поддержанных плоскостей → реконструкция остальных поверхностей → удаление неподдержанных частей → decimation → перенос RGB.
- Не превращать каждый найденный bounding box в сплошную стену: поддержка поверхности должна проверяться точками, большие дверные/оконные проёмы нельзя автоматически зашить.
- Допустимо сравнить BPA и обрезанную Poisson-реконструкцию, выбрать результат по реальным mesh-превью и численным расстояниям до измерений. Не тратить время на бесконечный перебор методов.
- Цель — до ~200–300 тысяч треугольников суммарно и желательно до 10 MB на оба GLB. Если реальная геометрия требует больше, сначала оценить вид и не жертвовать основными стенами ради формального числа.

## Контракт файлов

Существующие `public/data/manifest.json`, `exterior.bin`, `interior.bin` не менять.

Новые файлы: `public/data/exterior.glb`, `public/data/interior.glb`, `public/data/surfaces.json`.

```json
{
  "version": 1,
  "coordinateSystem": "right-handed-z-up",
  "assetUpAxis": "Y",
  "assetToSourceRotation": "x+90deg",
  "sourcePointCount": 147010451,
  "bounds": {"min": [0,0,0], "max": [1,1,1]},
  "interiorBounds": {"min": [0,0,0], "max": [1,1,1]},
  "models": [
    {
      "id": "exterior",
      "file": "exterior.glb",
      "byteLength": 0,
      "sha256": "actual sha256",
      "vertexCount": 0,
      "triangleCount": 0,
      "sourcePointCount": 49524269,
      "bounds": {"min": [0,0,0], "max": [1,1,1]},
      "method": "actual measured reconstruction method"
    }

```

Пример содержит только форму: все числа bounds/counts/size в результате должны происходить из реального mesh/источника; обязательны обе модели `exterior` и `interior`. В каждом GLB реальные треугольники, normals, vertex color и standalone buffers; нет external URI, Draco, внешних texture/decoder dependencies.

### Оси и цвет

Исходные XYZ — правая Z-up. GLB должен быть нормальным glTF Y-up: применить к исходной геометрии переход Rx(-90°) (возможно на root-node), сохранив общий origin. При загрузке frontend помещает glTF scene в родительский Group с Rx(+90°) и возвращает измеренную систему координат. Одинаково преобразовывать позиции и нормали; не отражать одну ось. У обоих объектов после восстановления должны совпадать source frame и камерные координаты существующего маршрута.

Цвет `COLOR_0` в GLB должен быть Linear-sRGB, а не исходные sRGB bytes, ошибочно интерпретированные как linear. Возможен FLOAT RGB для точности либо нормализованный integer с документированной конверсией. Не удваивать гамма-коррекцию. Roughness 1, metallic 0, doubleSided при необходимости; освещение нейтральное.

## Сайт

- Основной вид по умолчанию — «Поверхности», настоящий draw треугольников.
- «Точки» — только опциональное сравнение; не загружать 24 MB старых bin до запроса этого режима.
- Сохранить scroll, пять глав, orbit/возврат, Z-срез, error/retry, reduced-motion, desktop/mobile.
- Режим готовности различает получение байтов, parsing, реальный draw. Диагностика дополняется `displayMode`, `renderedTriangles`, `loadedModels`/mesh counts; не считать vertices GPU points.
- Z-срез — реальное отсечение поверхности в исходной мировой оси Z.
- Не загружать внешний CDN и платные сервисы; данные и код статические на том же Pages.

## Приёмка

1. Изображение стало сплошными читаемыми поверхностями, а не вариантом отрисовки точек.
2. Фасад, крыша, основные внутренние полы/стены/лестница сохраняют реальную форму; нет огромных ложных крышек, летающего мусора и сплошных заполнений всего AABB.
3. Измерены размеры, треугольники, удалённый шум и расстояния mesh до исходного/агрегированного облака; цифры не заменяют визуальный осмотр.
4. Модель легче первой веб-выборки и пригодна для mobile.
5. Поведение/публикация подтверждаются реальными тестами и HTTPS-чтением после независимого ревью. Полные LAS, временные кандидаты и private evidence не идут в Git.
